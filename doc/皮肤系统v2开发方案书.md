# LumiLuna 皮肤系统 v2 开发方案书（ZIP 资产包 · 背景图 · 图标包 · 布局开放）

> 版本：v2 草案 · 2026-08-23
> 前置：[皮肤系统开发方案书 v1](./皮肤系统开发方案书.md)（已实现并随 v1.1.x 发布）；[皮肤开发指南](./皮肤开发指南.md)
> 状态：待评审。§2 的决策沿用 v1 访谈确立的哲学（严格校验 / 远程引用知情 / 逃生通道 / 播放器软隔离）直接推导，标注【可推翻】，评审时可逐条质疑。

## 1. 背景与目标

v1 已交付：JSON 皮肤（结构化令牌 + 任意 CSS 注入）、固化存储、种子色 opt-in 适配、单模式锁定、安全模式逃生、四款内置皮肤。v1 方案书 §15 预留的 v2 方向中，本次按需求实现四项：

1. **ZIP 打包**：皮肤可携带资源文件（图片、字体），摆脱单 JSON + data URI 的体积限制；
2. **背景图片**：全应用背景图层（浅/深分别配置、遮罩浓度可调）；
3. **图标样式**：自定义图标包（SVG 逐名替换 / 整字体替换两种模式），支持引用外部来源；
4. **UI 布局**：开放布局令牌（带取值范围）+ 公开结构区域钩子，皮肤可安全地改变界面布局密度。

**不做的**（继续留在展望）：导出当前配置为皮肤、开发者热重载、皮肤市场/分享码、整页结构重排（如顶栏导航）、播放器区域的官方适配。

## 2. 决策记录（沿用 v1 哲学推导）

| # | 议题 | 决策 | 理由 |
|---|------|------|------|
| D1 | ZIP 解包位置 | **Rust 侧**（新增 `zip` crate），前端不碰压缩包 | 延续「前端不直接触碰磁盘」原则；路径穿越/炸弹防护在 Rust 做最可靠 |
| D2 | 大二进制过 IPC | 解压/落盘全在 Rust，**IPC 只过 JSON 原文与文件清单**；入参走 bytes（`Vec<u8>`）统一三种来源（文件对话框路径、拖拽路径、内置种子 fetch） | 避免逐文件 base64 过桥的体积与性能问题 |
| D3 | 导入事务性 | **两阶段 staging**：解压到 `skins/.staging/<uuid>/` → TS 校验 → `skin_commit` 原子换入；校验失败 `skin_abort` 丢弃 | 坏皮肤永远进不了正式库；覆盖更新有回滚（旧目录改名后删） |
| D4 | 资源寻址 | 皮肤内相对路径由**加载器统一重写**为 `asset://` 绝对地址（`convertFileSrc`，assetProtocol 已启用）；结构化 `background`/`icons` 字段也可直接填 http(s) URL（进远程引用确认清单） | 皮肤作者写 `url(assets/bg.jpg)` 即可；外部引用与 v1 CSS 通道共用同一知情确认流 |
| D5 | 图标替换实现 | **免重构**：SVG 模式用 MutationObserver 按图标名打标 + 注入按名生成的 CSS；字体模式用同名 `@font-face` 覆盖。不做 240 处 / 29 文件的组件化改造 | 全量替换 `material-symbols-outlined` 为 `<LmIcon>` 工程量大且引入回归面；observer 仅在激活对应皮肤时挂载，动态渲染（v-for 图标名）自动捕获 |
| D6 | 布局能力边界 | **布局令牌白名单开放（带硬范围校验）+ `data-lm-region` 结构钩子公开**；整页结构重排不承诺（任意 CSS 理论上可做，官方不支持） | 令牌化保证极端值撑不破界面；钩子给皮肤 CSS 稳定的选择器面，避开 scoped 哈希 |
| D7 | 背景图层挂载 | App.vue 新增独立背景层（z-index 0，内容之上罩遮罩），仅普通页面渲染；播放器页/桌面歌词页不承诺背景（D9 软隔离延续） | 不动现有 app-shell 布局；与毛玻璃表面天然配合（`--lm-scrim-surface` 本就是半透明） |
| D8 | v1 兼容 | `formatVersion: 1` 皮肤完全不受影响；`2` 为新格式。v1 应用遇 v2 皮肤被 formatVersion 校验拒绝并提示更新（v1 已实现该文案路径） | 双格式共存，零迁移成本 |
| D9 | 播放器边界 | 沿用 v1 软隔离：背景/图标/布局对播放器区域无官方承诺 | 不变 |

## 3. ZIP 包格式 v2

### 3.1 目录结构

```
my-skin.zip
├── skin.json              ← 唯一入口，formatVersion: 2（必须位于压缩包根）
└── assets/                ← 任意子目录结构，路径由 skin.json 引用
    ├── bg-light.jpg
    ├── bg-dark.jpg
    ├── icons.woff2        ← 字体模式
    └── icons/             ← SVG 模式（文件名 = Material Symbols 图标名）
        ├── home.svg
        └── favorite.svg
```

### 3.2 skin.json 增量字段（相对 v1）

```jsonc
{
  "formatVersion": 2,
  "manifest": { /* v1 字段不变；v2 皮肤建议 minAppVersion: "1.2.0" */ },
  "tokens":  { /* v1 不变 + §6 布局令牌 */ },
  "css":     "...url(assets/x.png)...",   // 相对 url() 由加载器重写为 asset://
  "background": {                          // 可选；浅/深分别配置
    "light": { "image": "assets/bg-light.jpg", "size": "cover", "position": "center", "overlay": 0.12 },
    "dark":  { "image": "https://cdn.example/dark.jpg", "overlay": 0.35 }   // 外链可，进确认清单
  },
  "icons": {                               // 可选；二选一模式
    "mode": "svg",
    "svg":  { "dir": "assets/icons" },
    "font": { "file": "assets/icons.woff2", "css": "assets/icons.css" }    // css 可选（附加 @font-face 变体裁剪等）
  }
}
```

固化后的磁盘形态：`skins/<id>/skin.json + assets/**`——与 v1 目录制完全同构，`skin_list`/`skin_load`/`skin_delete` 无需改动。

### 3.3 Rust 侧防护（解包时执行）

- 条目数 ≤ 200，解压总量 ≤ 50 MB（zip 炸弹防护）；
- 条目路径禁止绝对路径 / `..` / 反斜杠穿越 / 盘符，一律拒绝整个包；
- `skin.json` 必须存在且 ≤ 256 KB；单文件 ≤ 10 MB（字体 ≤ 5 MB）；
- `.staging/` 目录对 `skin_list` 不可见；启动时清扫遗留 staging。

## 4. 背景图系统

**加载器产出**（按当前浅/深模式写入 CSS 变量）：

```
--lm-skin-bg-image    asset://... 或 https://... 或 none
--lm-skin-bg-size     cover | contain | <len>（默认 cover）
--lm-skin-bg-position center（默认）
--lm-skin-bg-overlay  遮罩 rgba（浅色基白 / 深色基黑，alpha = overlay 值 0–1）
```

**DOM**：App.vue 根部新增：

```html
<div v-if="hasSkinBg && !isPlayerPage && !isDesktopLyricsPage" class="lm-skin-bg" aria-hidden="true"></div>
```

`position: fixed; inset: 0; z-index: 0;` 背景层 + `::after` 遮罩；app-shell 背景在该激活时保持现有 `--md-sys-color-background`（半透明毛玻璃表面叠上去即是「图片透出容器」的效果，`--lm-scrim-surface` 令牌可调玻璃浓度）。配套新令牌 `--lm-surface-blur`（默认 28px，范围 0–48px）让皮肤统一控制毛玻璃模糊量。

## 5. 图标系统

### 5.1 SVG 逐名替换（`icons.mode: "svg"`）

- 包内 `dir` 目录的文件名即 Material Symbols 图标名（如 `home.svg`），构建皮肤清单 `{ "home": "asset://…/home.svg", … }`（Rust staging 返回文件清单，TS 侧过滤出该目录下的 `.svg`）；
- 激活时挂 MutationObserver：扫描 `.material-symbols-outlined`，`textContent.trim()` 命中清单 → 设 `data-lm-icon="<name>"`；同时注入按名生成的样式表（背景图替换 + 原字素透明化 + `contain` 尺寸）；
- DOM 后续变化（虚拟列表、v-for 动态图标名）由 observer 自动补标；卸载/切换皮肤时移除全部 `data-lm-icon`、样式表并断开 observer；
- 已知取舍（写入指南）：被替换的图标失去字体变体轴（FILL/wght/GRAD）；图标名以 [Material Symbols 名称表](https://fonts.google.com/materialicons) 为准。

### 5.2 整字体替换（`icons.mode: "font"`）

注入 `@font-face { font-family: "Material Symbols Rounded"; src: url(asset://…) }` 覆盖内置字体——全部图标统一换风格、连字机制不变、变体轴是否可用取决于字体本身（作者可附 `css` 设默认 `font-variation-settings`）。适合「整套线性/圆角风」分发；门槛是需自备 woff2。

### 5.3 外部来源

- 结构化字段（`background.*.image`、`icons.font.file`）允许 http(s)，校验器并入远程引用警告清单，确认后放行（与 v1 CSS 通道同一条知情流）；
- 纯 CSS 通道（`@font-face` / `url()` 写在 `css` 里引外部）v1 已支持并带警告，继续有效。

## 6. 布局能力开放

### 6.1 布局令牌（进入 tokens 白名单，带硬范围）

| 令牌 | 默认 | 允许范围 | 说明 |
|------|------|----------|------|
| `--lm-nav-width` | 88px | 56–240px | 侧栏宽度（收窄成图标条 / 加宽带完整标签） |
| `--lm-content-pad` | 24px | 0–64px | 内容区留白 |
| `--lm-titlebar-height` | 48px | 32–64px | 标题栏高度 |
| `--lm-miniplayer-height` | 72px | 48–160px | 迷你播放条高度 |
| `--lm-surface-blur`（新） | 28px | 0–48px | 毛玻璃模糊量（配背景图调玻璃感） |

范围外一律拒收（严格校验哲学不变）。`theme.css` 与 `App.vue` 相应硬编码处改为引用令牌（`gap`、`blur(28px)` 等）。

### 6.2 区域钩子（`data-lm-region`）

在 App.vue 四个结构节点加稳定属性并在指南公开：

```
app-shell        data-lm-region="shell"
WindowTitleBar   data-lm-region="titlebar"
nav.nav-rail     data-lm-region="nav"
div.content      data-lm-region="content"
MiniPlayer 容器  data-lm-region="miniplayer"
```

皮肤 CSS 用 `[data-lm-region="nav"] { … }` 做布局微调（间距、对齐、显隐子元素），不受 scoped 哈希影响。**不承诺**整页结构重排（如导航移到顶部）——任意 CSS 理论上可尝试，坏了不保修。

## 7. 校验器 v2 增量（`skinSchema.ts`）

- `formatVersion === 2` 走新分支；`1` 走原逻辑不动；
- `background`：浅/深各自可选；`image` 必填且为「zip 清单内相对路径」或 http(s) URL；`overlay` 0–1；`size/position` 白名单值；
- `icons`：`mode` 二选一；svg 模式要求 staging 清单中该 dir 下至少 1 个合法命名的 `.svg`（`^[a-z0-9_]+$`）；font 模式要求 file 在清单内且扩展名 `woff2|woff|ttf`；
- 布局令牌按 §6.1 范围校验（新增「令牌 → 范围」表驱动，报错文案带允许区间）；
- 远程引用检测扩展到结构化字段（不止 `css`）；
- 资产引用存在性校验依赖 staging 返回的文件清单（`validateSkin` 增加 `opts.files?: string[]`）。

## 8. 命令与模块增量

**Rust（`commands/skin.rs` + `Cargo.toml` 加 `zip` crate，默认 features）**：

| 命令 | 签名 | 职责 |
|------|------|------|
| `skin_stage_zip` | `(bytes: Vec<u8>) -> { staging, json, files }` | §3.3 防护下解压到 staging，返回 json 原文与文件清单 |
| `skin_commit` | `(staging, id) -> ()` | 原子换入 `skins/<id>/`（旧目录先改名再删 = 更新回滚） |
| `skin_abort` | `(staging) -> ()` | 丢弃 staging |
| `skin_read_file_bytes` | `(path) -> Vec<u8>` | 对话框/拖拽路径读字节（统一汇入 bytes staging） |
| `skin_dir` | `() -> String` | skins 绝对路径（前端 `convertFileSrc` 拼 asset://） |

**前端**：

- `skinSchema.ts`：§7 全部规则 + 类型；
- `skinLoader.ts`：css 相对 `url()` 重写（基于 `skin_dir()` + id）、背景变量写入、SVG observer / 字体注入与完整清理、资产清单缓存；
- `skins.ts` store：导入分支（`.zip` → bytes → staging → 校验 → 远程确认 → commit）；种子播种支持从 `public/skins/*.zip` fetch（走同一条 bytes 链路）；
- `App.vue`：背景层 + `data-lm-region` 钩子；
- `SettingsView.vue` / `shared/i18n.ts`：导入过滤器加 `.zip`、皮肤卡「背景/图标/布局」能力徽标、新增文案；
- 构建脚本 `scripts/make-skins.mjs`（devDep `fflate` 打 zip）：`src/skins-src/showcase/` → `public/skins/lumiluna.showcase.zip`，接入 `npm run build` 前置——演示皮肤源文件可读可维护，产物 zip 不入库；
- `capabilities/index.ts` + `mock.ts`：新命令封装（mock 内存 staging 模拟）。

## 9. 兼容性

- v1 皮肤（`formatVersion: 1`）零影响；v1 应用遇 v2 → 现有「formatVersion 不受支持」拒绝路径提示升级；
- v2 皮肤建议 `minAppVersion: "1.2.0"`；
- 安全模式（`--safe-mode`）语义不变：背景/图标/布局随皮肤整体跳过；
- 种子色、模式锁、覆盖更新、删除记忆（`hiddenBuiltinSkins`）全部对 v2 生效。

## 10. 安全清单

zip 炸弹与路径穿越（§3.3）；SVG 仅作 `background-image`/`<img>` 等脚本安全上下文引用，不 innerHTML 注入；远程引用统一知情确认；assetProtocol scope 现为 `**`（沿用现状并在指南披露，v3 再议收紧）；大文件上限防资源滥用；`--safe-mode` 逃生覆盖全部新增能力。

## 12. 测试计划（增量）

- 校验器：background/icons 每字段正反例；布局令牌边界值（56.01px 拒）；远程结构化 URL 进警告；v1 文档回归；
- staging：炸弹（高压缩比）、`../` 穿越、缺 skin.json、清单外引用拒收；
- 加载器：css `url()` 相对/嵌套引号重写；observer 对动态节点补标；字体注入与卸载；背景浅深切换变量重放；
- 集成：v1 皮肤与 v2 皮肤同库共存；激活 v2 → 删除 → 回退默认无残留；`--safe-mode` 下背景/图标不加载。
