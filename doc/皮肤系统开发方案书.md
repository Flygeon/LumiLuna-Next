# LumiLuna 皮肤系统开发方案书（v1）

> 版本：v1 草案 · 2026-08-23
> 状态：待评审
> 范围：应用 UI 皮肤化（不含音乐播放器部分的官方适配）；本方案只做设计，不含实现

---

## 1. 背景与目标

LumiLuna 目前只有一套 Material Design 3 风格：`src/tokens/theme.css` 以 CSS 变量承载全量 MD3 令牌（颜色 ×浅/深两套 + 形状 + 字号阶梯 + 动效 + `--lm-*` 应用级令牌），`src/utils/dynamicTheme.ts` 支持由一个种子色实时生成整套颜色令牌（内联样式覆盖 `<html>`）。

**目标**：引入皮肤（Skin）系统，让用户可以从外部文件导入 UI 风格预设，固化保存在应用数据目录，并在设置中管理与切换。

**核心需求**：

1. 从外部文件（`.json`）导入皮肤，入口含文件对话框与拖拽；
2. 皮肤数据解析（严格校验）、存储（固化到应用数据目录）、加载（注入生效）；
3. 同 ID 重复导入 = 覆盖更新；
4. 设置页新增皮肤管理区块；
5. 保留现有种子色动态配色作为「默认皮肤」的能力；
6. 播放器部分（`--am-*` 令牌与 PlayerView/MiniPlayer/LyricsView 专属样式）**不在 v1 皮肤支持范围**，采用文档约定软隔离。

## 2. 需求决策记录（经三轮设计拷问定案）

| # | 议题 | 决策 | 理由 |
|---|------|------|------|
| D1 | 皮肤文件格式 | **单 JSON 起步**，schema 预留 `formatVersion` 与 `assets` 字段，v2 再上 ZIP 包 | v1 免解压、易校验、易分享；为多资源皮肤留演进空间 |
| D2 | 可定制范围 | **允许任意 CSS 注入** + 结构化令牌表（可选） | 表现力最大；配合严格校验、远程引用警告、逃生通道兜底 |
| D3 | 与种子色配色方案的关系 | 种子色**仅对默认皮肤开放**；皮肤作者可在 manifest 一行声明 `seedColor: true` 适配（**默认关**） | 皮肤配色是作者完整意志，不被种子色意外覆盖；适配是 opt-in |
| D4 | 深色模式策略 | 由皮肤作者声明 `modes`（`["light"]` / `["dark"]` / `["light","dark"]`），应用提供接口；激活仅单模式皮肤时**自动切到支持模式并锁定浅/深切换**，换回多模式皮肤即解锁 | 作者自由适配；体验统一 |
| D5 | CSS 远程引用（`url()` / `@import` 指向 http(s)） | **警告但不阻止**：导入时检测并列出全部远程引用，用户确认后放行 | 兼顾表现力与知情权；当前 `tauri.conf.json` CSP 为 `null`，技术上可行 |
| D6 | 坏皮肤逃生通道 | **启动逃生参数 + 设置重置按钮**双保险 | 皮肤可能把 UI 改坏到点不开设置，必须有不依赖 UI 的逃生路 |
| D7 | 导入校验策略 | **严格校验拒绝**：不合规直接拒收并给出用户可读的具体错误 | 皮肤库永远干净，坏皮肤进不来 |
| D8 | 重复导入策略 | **同 ID 覆盖更新**，提示版本变化（如「已从 1.0.0 更新到 1.2.0」） | 符合「装新版」直觉，作者好发更新 |
| D9 | 播放器隔离边界 | **软隔离（文档约定）**：皮肤 CSS 理论上可命中全应用任何选择器，但官方不承诺、不保证、不校验播放器部分；`--am-*` 令牌不进令牌白名单 | Shadow DOM 硬隔离需大重构，v1 不现实；静态剥离对任意 CSS 不可靠 |
| D10 | v1 附加能力 | **内置示例皮肤 + 拖拽导入**；不含导出、不含开发者热重载 | 示例皮肤即文档即演示；拖拽是导入的自然入口 |

## 3. 总体架构

```
外部皮肤文件 (.json)
   │  ① 文件对话框选择            ② 拖拽到窗口任意位置
   ▼
capabilities.skinReadExternalFile(path)  ──►  Rust: 读文件原文返回
   ▼
skinSchema.validate(raw)  ──►  错误 → 拒绝（用户可读错误列表）
   │                            警告（远程引用）→ 确认对话框 → 放行/取消
   ▼
capabilities.skinSave(id, json)  ──►  Rust: 固化写入 {app_data_dir}/skins/<id>/skin.json（原子写，同 ID 覆盖）
   ▼
Pinia skins store（刷新皮肤列表）
   ▼
用户激活（设置页点击，即时生效）
   ▼
skinLoader.applySkin(skin, dark)
   ├─ 皮肤 CSS ──►  <style id="lm-skin-css"> 注入（作者自行用 [data-theme="dark"] 适配深色）
   └─ 皮肤结构化令牌 ──►  内联 CSS 变量写到 <html>（沿用 applySeedColor 的覆盖机制）
```

**与现有机制的层次关系**（优先级从低到高）：

1. `theme.css` 静态默认令牌（`:root` 浅色 + `[data-theme="dark"]` 深色）——永远是兜底；
2. 皮肤 `<style id="lm-skin-css">`——普通 CSS，按选择器特异性生效，作者可写 `:root {}` / `[data-theme="dark"] {}`；
3. 皮肤结构化令牌的内联样式（`documentElement.style.setProperty`）——高于任何选择器；
4. 种子色令牌内联样式（仅当皮肤为默认，或皮肤声明 `seedColor: true` 且用户选了种子色）——最后写入，同层覆盖 3。

> 该层次复用了 `dynamicTheme.ts` 已验证的「内联样式盖住两套 `[data-theme]` 规则」机制，皮肤作者与现有代码共享同一套心智模型。

## 4. 皮肤文件格式规范 v1

### 4.1 完整示例

```jsonc
{
  "formatVersion": 1,
  "manifest": {
    "id": "com.example.midnight",        // 必填，唯一键，见命名规则
    "name": "午夜",                       // 必填，显示名
    "version": "1.0.0",                   // 必填，semver
    "author": "Someone",                  // 必填
    "description": "AMOLED 纯黑皮肤",      // 可选，≤200 字符
    "minAppVersion": "1.2.0",             // 可选，低于则拒绝导入
    "modes": ["dark"],                    // 必填，{"light","dark"} 的非空子集
    "seedColor": true,                    // 可选，默认 false —— 一行开关：适配种子色
    "accent": "#8BB9F0"                   // 可选，列表缩略圆点展示色（仅展示用）
  },
  "tokens": {                             // 可选：结构化令牌（白名单键，见 4.3）
    "light": { "--md-sys-color-primary": "#005BC1", "...": "..." },
    "dark":  { "--md-sys-color-primary": "#9ECAFF", "...": "..." }
  },
  "css": "/* 任意 CSS，浅深适配由作者用 [data-theme=\\"dark\\"] 自行完成 */\n:root { --lm-scrim-surface: rgba(8,8,10,.72); }\n[data-theme=\"dark\"] .lm-glass { backdrop-filter: blur(40px); }",
  "assets": null                          // v1 预留，必须缺省或 null
}
```

### 4.2 字段规则

| 字段 | 必填 | 约束 | 校验失败示例 |
|------|------|------|--------------|
| `formatVersion` | 是 | 恒为 `1`（其他值拒绝并提示「需更新应用」） | `2` |
| `manifest.id` | 是 | `^[a-z0-9][a-z0-9-]{1,62}(\\.[a-z0-9-]+)*$`，即小写字母/数字/连字符，可点分；同时是存储目录名 | `My Skin`、含 `/\\` 等 |
| `manifest.name` | 是 | 1–32 字符，非空白 | 空串 |
| `manifest.version` | 是 | semver 正则 `^\\d+\\.\\d+\\.\\d+(-[0-9A-Za-z.-]+)?$` | `1.0` |
| `manifest.author` | 是 | 1–64 字符 | 缺失 |
| `manifest.description` | 否 | ≤200 字符 | 超长 |
| `manifest.minAppVersion` | 否 | semver；导入时与当前应用版本比较，高于则拒收 | — |
| `manifest.modes` | 是 | 数组，值 ∈ `{"light","dark"}`，非空、去重 | `[]`、`["lite"]` |
| `manifest.seedColor` | 否 | 布尔，默认 `false` | 字符串 |
| `manifest.accent` | 否 | 合法 CSS 颜色字符串（≤64 字符） | `url(...)`、乱码 |
| `tokens` | 否 | 对象；`tokens.light` / `tokens.dark` 至少其一；键必须在白名单内；值为合法 CSS 颜色（≤64 字符，禁止 `url()`） | 未知键、`--am-*` 键 |
| `css` | 条件 | 字符串；`tokens` 与 `css` **至少提供其一**；总长度 ≤ 256 KB | 超 256 KB |
| `assets` | 否 | v1 必须缺省或 `null` | 任何非空值 |

### 4.3 结构化令牌白名单

- 全部 `--md-sys-color-*` 颜色角色（与 `theme.css` 定义一一对应；`--md-sys-color-scrim` 保持 `theme.css` 原值的设计理由同 `dynamicTheme.ts`——半透明蒙层不能被不透明色顶掉，故**不在白名单**）；
- `--md-sys-shape-*` 全部圆角令牌；
- `--md-sys-motion-*` 全部动效令牌；
- `--md-elevation-1/2/3`；
- `--lm-scrim-surface`、`--lm-hairline`（毛玻璃表面与发丝线）。

**排除**：`--am-*` 播放器令牌（D9 软隔离）；`--lm-nav-width` 等布局尺寸令牌与 `--md-sys-typescale-*` 字号阶梯（不进白名单，但任意 CSS 通道仍可覆盖——白名单约束的是「结构化数据」，不是最终能力）。

### 4.4 校验器输出

```ts
interface SkinValidation {
  ok: boolean;               // false 时 errors 非空，直接拒收
  errors: string[];          // 用户可读，中文，含字段路径，如「manifest.id：含非法字符」
  warnings: SkinWarning[];   // 不拦截，导入前需确认
  skin?: SkinDocument;       // ok 时给出规范化后的文档
}
interface SkinWarning {
  kind: "remote-ref";        // v1 唯一警告类型
  refs: string[];            // css 中检测到的全部 http(s) url()/@import 引用
}
```

远程引用检测：对 `css` 与令牌值做 `@import\\s+url?\\(|url\\(\\s*['"]?https?:` 的宽松匹配（宁误报不漏报），汇总去重后列出。

## 5. 存储设计（固化保存）

- **位置**：`{app_data_dir}/skins/<id>/skin.json`。每个皮肤一个以 id 命名的目录，为 v2 ZIP 资源（`<id>/assets/...`）预留结构。
- **目录即注册表**：不维护额外 registry.json，启动时扫描 `skins/` 目录、逐个解析 manifest。自愈（手删目录即卸载）、无状态漂移。
- **固化语义**：导入 = 校验通过后把**规范化 JSON 原文**写入上述路径；此后外部源文件与本应用再无关联（删除源文件不影响已导入皮肤）。
- **激活状态**：`settings.json` 新增字段 `activeSkin: string`（空串 = 默认皮肤），走 settings store 现有字段注册表，自动获得 load/save/watch。
- **无效条目**：启动扫描遇到解析失败/校验不过的目录 → 列表中显示为「损坏」条目（不加载、可删除），不让一个坏文件拖垮整个皮肤系统。
- **激活皮肤丢失**（目录被手动删除等）→ 自动回退默认皮肤 + 提示。

## 6. 加载与运行时设计

### 6.1 新模块 `src/utils/skinLoader.ts`

```ts
export function applySkin(skin: SkinDocument | null, dark: boolean): void
// - skin === null：移除 <style id="lm-skin-css">，清空皮肤内联令牌 → 回到 theme.css + 种子色
// - 注入：确保且仅确保一个 <style id="lm-skin-css">，textContent = skin.css
// - 令牌：将 skin.tokens[dark ? "dark" : "light"] 逐键 setProperty 到 documentElement
// - 切换深浅模式时以当前模式重放令牌（css 不动，无闪烁）
```

### 6.2 启动时序（挂在现有链路上，不新增入口）

```
main.ts 挂载 App
  └─ App.vue 启动：settings.load()        （现有）
       └─ skins.load()                     （新增：Rust skinList + 内置皮肤播种）
            └─ resolveTheme()              （现有，内部扩展）
                 ├─ data-theme 属性        （现有）
                 ├─ 皮肤：applySkin(当前皮肤, dark)          （新增）
                 └─ 种子色：applySeedColor(...)              （现有，加门控）
```

### 6.3 种子色门控（D3）

`resolveTheme()` 中调用 `applySeedColor` 的条件改为：

```
无激活皮肤（默认皮肤）           → 调用（现状行为，完全向后兼容）
激活皮肤且 skin.manifest.seedColor === true  → 调用（内联令牌最后写入，覆盖皮肤 tokens，
                                               皮肤 CSS 中 var(--md-sys-color-*) 引用自然吃到新色）
激活皮肤且未适配                 → 跳过（皮肤配色是作者的完整意志）
```

设置页「配色方案」行的可用性与此门控一致：不适用时置灰 + 提示文案（见 §9）。

> 皮肤作者适配种子色的方式（写入皮肤开发指南）：结构化令牌照常提供一套基础色，CSS 中颜色一律引用 `var(--md-sys-color-*)` 而非硬编码——开启 `seedColor: true` 后整套颜色即可被种子色重新驱动。

### 6.4 模式锁定（D4）

- 激活 `modes` 为单模式的皮肤：`applyTheme` 强制把 `theme` 切到该模式（`"dark"` 皮肤 → `"dark"`；`"light"` 皮肤 → `"light"`），并置 `lockedMode = true`；
- 锁定期间设置页浅/深/跟随系统三段控件置灰 + 提示「该皮肤仅支持深色模式」；
- 切回默认皮肤或双模式皮肤即解锁，`theme` 恢复为锁定前的用户选择（记忆于 store 内存，不持久化）。

### 6.5 逃生通道（D6）

1. **启动参数**：Rust 侧 `main.rs` 检测 `--safe-mode` 启动参数，经窗口初始 URL 查询参数（`?safe-mode=1`）传入前端；前端看到该标记则本会话跳过一切皮肤应用（仅默认主题），并弹提示「安全模式：皮肤未加载」。命令行用法写入用户文档与皮肤开发指南。
2. **设置重置**：设置页「恢复默认皮肤」按钮（永远有效，因为它位于默认主题渲染的 UI 内——安全模式下必然可达）。
3. **加载失败自愈**：激活的皮肤文件损坏/丢失 → 自动回退默认 + 提示，不白屏。

### 6.6 失败与降级

| 场景 | 行为 |
|------|------|
| 导入文件 JSON 损坏 | 校验器拒收，错误定位到「文件不是合法 JSON」 |
| 激活皮肤含警告级远程引用 | 已在导入时确认过，加载时不再拦 |
| 皮肤令牌引用了不存在的键 | 校验阶段已拒（白名单） |
| 皮肤 CSS 有语法错误 | 浏览器容错解析（与网页一致），不中断加载 |
| `skins/` 目录不存在 | Rust 首次访问时创建 |

## 7. Rust 命令设计（`src-tauri/src/commands/skin.rs`）

沿用现有 command 模式（纯函数 + `AppHandle`，`lib.rs` 的 `generate_handler!` 注册）：

| 命令 | 签名 | 职责 |
|------|------|------|
| `skin_read_external_file` | `(path: String) -> Result<String, String>` | 读取用户选中的外部皮肤文件原文（对话框/拖拽共用） |
| `skin_save` | `(id: String, json: String) -> Result<(), String>` | 固化写入 `skins/<id>/skin.json`（先写临时文件再 rename，原子覆盖 = 更新） |
| `skin_list` | `() -> Result<Vec<SkinEntry>, String>` | 扫描 `skins/` 目录，返回 `{ id, meta, status: "ok" \\| "broken" }`；`broken` 条目含失败原因 |
| `skin_load` | `(id: String) -> Result<Option<String>, String>` | 按需读取单个皮肤全文（供加载器） |
| `skin_delete` | `(id: String) -> Result<(), String>` | 删除皮肤目录；若删除的是激活皮肤，由前端先切回默认再调用 |

`SkinEntry` 结构放入 `shared/types.ts`（前端/Rust 共享类型约定与现有一致）。校验**全部在 TS 侧**完成，Rust 只做可信 IO——保持「前端不直接触碰磁盘」的 capabilities 原则（`capabilities/index.ts` 头注）。

**导入完整流程**（`importFromFile`）：

```
读原文 → validateSkin
  ├─ errors 非空 → 对话框列出错误，结束
  ├─ warnings（远程引用）→ 确认对话框列出全部 URL，「仍然导入 / 取消」
  └─ 通过 → skinSave（同 ID = 覆盖，比对新旧 version 提示「已更新 1.0.0 → 1.2.0」）
        → 刷新列表 → 询问是否立即启用（toast 带「启用」按钮）
```

**拖拽导入**：`onDragDropEvent` 的 `enter` 显示全窗口半透明遮罩（「松开以导入皮肤」），`drop` 取路径走同一 `importFromFile`，`leave` 撤遮罩；非 `.json` 文件提示格式不支持。

## 9. 设置 UI 设计（外观卡扩展）

现有「外观」卡（主题模式 / 语言 / 配色方案 / 关闭行为）新增**皮肤行**，置于「主题模式」与「配色方案」之间：

```
皮肤        ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
            │ 默认   │ │ 墨 ◎  │ │ 午夜◐ │ │ + 导入 │
            │ (动态) │ │ 1.0   │ │ 1.0   │ │        │
            └────────┘ └────────┘ └────────┘ └────────┘
            皮肤可从 .json 文件导入，拖拽到窗口也能导入
```

- **卡片列表**：默认皮肤永远第一（副标「动态配色」）；每个皮肤卡显示 accent 圆点（无 accent 用首令牌色）、名称、版本、作者 tooltip、模式支持图标（◐ / ☀ / ☛）、种子色适配标记（◎）、删除按钮（默认皮肤无）。损坏条目灰显 + 错误原因 tooltip + 仅可删除。
- **交互**：点击即激活并即时生效（与现有色板行为一致）；激活态高亮描边。
- **门控态**：
  - 激活皮肤未适配种子色 → 「配色方案」行置灰 + hint「当前皮肤未适配种子色，配色由皮肤作者定义」；
  - 模式锁定 → 「主题模式」三段控件置灰 + hint「该皮肤仅支持深色 / 浅色模式」；
- **恢复默认皮肤**按钮放在皮肤行末尾的次要位置。
- 删除已激活皮肤：确认对话框 → 先切默认再删。

## 11. 安全与边界

1. **无代码执行**：皮肤是纯数据（JSON + CSS 字符串），不涉及 JS 求值、不使用 `eval`/动态 `<script>`。
2. **远程引用知情**（D5）：检测 `http(s)` 的 `@import`/`url()`，导入前列清单确认。当前 CSP 为 `null` 故均可生效；**若未来启用 CSP，远程引用可能失效**——已列入 v2 注意项。
3. **体积与数量上限**：单个 `css` ≤ 256 KB；皮肤总数不设硬限（目录自愈，无性能放大器——启动只读 manifest 列表，全文按需加载）。
4. **白名单**（§4.3）：结构化令牌键与值严格校验（颜色格式、禁 `url()`）。
5. **逃生通道**（§6.5）：`--safe-mode` 启动参数 + 设置重置按钮 + 坏文件自愈。
6. **播放器软隔离**（D9）：皮肤开发指南明示——播放器区域样式随时可能因任意 CSS 受影响，但非官方支持范围，版本升级后播放器观感变化不视为皮肤兼容性缺陷；`--am-*` 令牌永不进白名单。
7. **id 即目录名**：id 正则（§4.2）已排除路径穿越字符（`/`、`\\`、`..` 由首字符与字符集规则排除），Rust 侧再以「id 校验过的皮肤只来自 skin_save」保证写入路径安全。

## 14. 测试计划

- **校验器单测（M1）**：合法最小皮肤；每条 §4.2 规则的反例；远程引用检测（`@import url(...)`、`url('https://...')`、大小写、空格变体）；256KB 边界。
- **存储（M2）**：导入→列表→重导入同 id（覆盖 + 版本变化）；删除激活中皮肤（前端先回退）；目录被外部删除后的启动自愈；`broken` 条目展示。
- **运行时（M3）**：注入后 `<style>` 唯一性；切换皮肤移除旧 style；默认皮肤下 `applySeedColor` 行为与现状完全一致（回归）；`seedColor: true` 皮肤 + 种子色 → 皮肤 CSS 中 `var(--md-sys-color-primary)` 取到种子色；dark-only 皮肤激活 → 自动切深色 + 三段控件锁定 + 切回默认解锁并还原先前模式；`--safe-mode` 启动不加载皮肤。
- **UI/交互（M4）**：门控置灰逻辑；拖拽遮罩与非法文件提示；导入确认对话框（错误列表/远程引用列表两种）。
- **回归**：不开启任何皮肤时，全应用观感与 v1.1.0 完全一致（零行为变化是硬指标）。
